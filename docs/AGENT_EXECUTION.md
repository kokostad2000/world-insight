## 可直接复制给开发 Agent 的完整指令

你负责将《国际局势研究看板 PRD v1.1》实现为可在我的 Mac 上运行的应用。请直接执行实现、集成、验证和修复，持续完成下面定义的工程目标，不停留在分析、计划、文档或静态演示。

### A. 目标与范围

- 阅读完整 PRD，以 FR-01 至 FR-15、AC-01 至 AC-36、第 11.6 节交付清单及第 12 节验证要求为需求基线。
- 本轮实现全部 P0；P1 和预留能力完成 PRD 要求的接口、配置和未启用状态，不自动扩大为实际付费接入或额外产品。
- 产品主线是“议题 → 资料和证据 → 事件与说法 → 判断和情景 → 变化跟踪 → 复盘”，不是只展示几个数据卡片。
- 本轮持续开发目标为完成 M1—M3 及当前条件下可实际执行的 M4 检查，并交付七天真实试运行所需的运行、记录和验收入口。完整 M4 仍须等待真实观察期满足，不修改或取消 PRD 的最终验收要求。

### B. 初始检查与自主决策

1. 核对当前项目目录、仓库状态、已有文件、项目规则、操作系统、架构及必要运行依赖。保留已有修改与资料。
2. 如果没有应用代码，在当前明确选中的项目目录建立项目结构；若目录不明确，只澄清目录这一阻断项，不把产品问题重新询问一遍。
3. 依据 PRD 默认假设自主处理常规细节：中文、桌面优先、个人私有运行、免费数据、AI 默认关闭。明显影响范围、数据保留或支出的决定需要单独说明。
4. 评估独立实现与复用 World Monitor 的成本、许可及复杂度，选定足以满足 P0 的最简可维护架构，记录理由后开始实施。不要为等待常规技术选型确认停工，也不要在没有证据的情况下反复换技术栈。
5. 允许在项目范围内创建代码、安装项目依赖、执行必要验证和运行本地开发服务。未经另行明确授权，不创建或推送 GitHub 仓库、不部署公网、不购买服务、不绑卡、不发送外部消息。

### C. 持续保存执行状态

在目标仓库维护以下文件；如果已有同用途文档，更新原文档，不重复建立相互矛盾的副本：

- `docs/PRD.md`：需求基线，保留 v1.1 内容；不要通过删除或降低要求让测试通过。
- `docs/IMPLEMENTATION_PLAN.md`：里程碑、执行顺序、文件归属、架构决策和每阶段验证方式。
- `docs/ACCEPTANCE.md`：FR 与 AC 的逐项映射、实现位置、验证层次、状态、执行环境及证据位置。
- `docs/PROGRESS.md`：当前版本、已完成事项、正在做什么、下一步、阻塞、已运行命令和真实结果。

验收状态使用“未执行／通过／失败／阻塞／待观察”。区分已实现与已验证；每条通过记录必须有可复查证据，不能仅引用自己的总结。

每个里程碑结束更新状态并继续下一步，不等待用户反复发送“继续”。发生上下文压缩、会话恢复或交接时，先核对这些文件和代码实际状态，从未完成事项继续。

### D. 执行顺序

1. 确定数据对象、领域 API、数据目录、迁移机制和来源配置；建立统一错误与降级状态。
2. 打通最小真实闭环：创建议题 → 登记原文材料 → 建立说法／事件 → 保存判断 → 重启后仍可读取和修改。
3. 实现免费新闻发现、RSS、国家背景、证据版本、去重及引用关系；将真实源、模拟数据与手工材料明确区分。
4. 完成首页变化、议题档案、证据详情、地图、判断／情景／影响路径、纠错传播、站内提醒和复盘导出。
5. 完成本地一键启动、配置检查、独立数据目录、一致性备份恢复、更新及迁移失败回退。
6. 进行整体浏览器验收、真实免费源验证、故障注入及回归修复；完成后整理可运行交付和长期试运行记录入口。

允许调整实现顺序以减少依赖等待，但不得遗漏 P0。应持续保留可启动、可验证的版本，不到最后才第一次集成。

### E. 并行开发与集成

如支持子 Agent，可将界面、领域与数据、运行交付、独立审查等可并行任务交给子 Agent。主 Agent 保留整体架构、任务边界和集成责任。

- 先约定领域模型与 API，再并行实现。
- 每个写入任务使用独立 worktree，或明确独占目录；共享模型、数据库迁移、依赖锁文件、启动与更新脚本指定唯一负责人。
- 不共享可写测试数据库、采集实例或同一测试端口；有依赖的任务按顺序执行。
- 合并后由主 Agent 重新验证整体行为。子任务分别通过不代表集成产品通过。
- 没有子 Agent 能力时由主 Agent 顺序完成，不因此阻塞。

### F. 数据与费用边界

- 不启用收费 API、绑卡试用或自动充值；配额用尽时暂停采集，已有资料仍可阅读。
- 缺少可选 Key 时实现明确的未配置状态并继续核心工作。真实访问权限不足时，记录具体阻塞，不用假数据冒充已联通。
- 免费源不可用时可以按 PRD 选择等效来源，记录差异、授权与理由；不能静默撤销验收条件。
- 新闻、声明、观测、判断和预测保持区分。无数据、未知、零值、争议、陈旧和未配置不得混同。
- 演示与异常测试可使用明确标记的 fixtures；正常运行不自动展示成真实国际事件。
- 密钥、数据库、个人记录、备份和运行日志不提交至 GitHub。代码同步不代替数据备份。

### G. 验证与修复要求

每个里程碑都执行与其相关的验证。发现问题先定位和修复，再验证；不要通过禁用功能、删测试、放宽断言或伪造结果完成验收。

必须区分以下证据层次：

1. 静态检查：类型、构建、规范及适用的安全检查。
2. 行为测试：领域规则、版本冲突、去重、纠错、未知状态和预算行为。
3. 整体测试：真实后端、数据库、前端与浏览器操作的完整闭环。
4. 真实源验证：按 PRD 接入并观察免费源，记录时间、环境、请求结果与限额。
5. 本地运行验证：实际 Mac 上启动、停止、重启、数据保留、备份恢复、更新和回退。
6. 长期观察：连续七天及用户使用效率验证，保留真实记录。

优先自动化确定性、关键行为和回归用例；需要人工操作或长期观察的项保留明确步骤和记录方式，不以源码扫描替代行为测试。

至少真实完成：新代码目录启动、重复启动与停止、备份到空实例恢复、正常版本更新、迁移失败回退、未提交修改保护。恢复后必须在浏览器读取旧研究记录并继续编辑。所有故障、恢复和升级演练使用隔离测试数据，不能破坏用户已有资料。

不得将 Linux 上的脚本测试标为 macOS 验收，不得将健康检查成功标为整个页面可用，不得将本地 mock 成功标为外部接口已联通。

在具备工具和独立审查能力时，安排一次实现者之外的审查，重点检查数据丢失、更新回退、证据状态和范围遗漏；修复实质问题后复测。

### H. 缺失条件与停止规则

- 常规错误、测试失败或某个可选来源不可用时，继续排查或处理其他独立工作，不因遇到一个问题就停止整个任务。
- 真正需要用户介入的情况包括：目标目录无法确定、必要凭据只能由用户提供、当前环境不具备验证能力、权限被阻止、涉及未授权费用或破坏性操作。
- 需要用户介入时，用最小问题说明受阻动作、原因、已尝试的方法及剩余可做工作；同时继续不受影响的任务，不绕过限制。
- 如宿主因额度、连接或运行限制中断，先保存进度、证据及恢复入口；不能承诺会话结束后仍自动执行。重新继续时从记录恢复。
- 工程目标尚有失败、未执行或关键阻塞时，不能报告“全部完成”。最终状态必须按实际分为工程已验收、部分完成有阻塞、或待长期观察。

### I. 七天试运行边界

PRD 第 12.1 节要求五个真实议题连续运行七天，并包含资料抽查和使用效率验证。这些不能通过模拟时间、伪造日志或一次短测试替代。

本次开发完成后交付试运行的启动／停止入口、采集记录、检查点、数据缺口记录和验收方法。真实运行安排需明确电脑保持可用的条件、开始时间及检查方式；没有实际启动和记录时，只能说“已准备试运行”，不能说“试运行进行中”。

七天未满时报告“M3 工程阶段完成，M4 尚待真实试运行验收”。需要定时复查或持续任务时按宿主能力和明确授权另行配置，不暗示当前对话结束后 Agent 会自动持续观察。最终 PRD 完成状态要在实际门槛满足后更新。

### J. 最终交付内容

- 本地项目绝对路径、当前程序／数据库版本及 Git 提交信息；有远程推送时另提供真实仓库地址和分支。

- FR-01—FR-15、AC-01—AC-36 的验收矩阵，保留通过证据及未完成原因。
- 真实数据源、实际运行环境、浏览器验证结果与明确标识的演示数据范围。
- 已修复问题、当前已知限制，以及七天真实试运行的实际状态和后续检查方法。
