## 启动条件

1. 工程 M3 的 AC-01—AC-36 与 Mac 操作演练通过后，选择五个真实议题。推荐研究范围模板已内置，不预填任何当前结论。
2. 用户确认实际议题、数据目录与采集范围。开启免费来源，检查每源许可、预算、历史支持和最后成功时间。
3. 明确实际开始时间、Mac 可用时段、睡眠/断网影响、每日检查人。应用进程停止或电脑睡眠期间无法声称持续在线；补采和无法补齐区间必须保留。
4. 每日收集真实采集任务、成功/失败、重复、延迟、配额和人工纠错；不修改系统时间、不构造七天日志。

## 结构质量与官方材料

- 至少登记并复核十条不同类型官方材料（声明、政策、数据说明等）；每条记录原URL、发布者、发布时间精度、许可范围、允许摘录、议题及登记/复核人和时间。
- 抽查不少于50材料、20事件/说法、10判断：引用、版本、时间、出处、未知项、核查状态逐项核验。可单独记录结构错误，不等同预测准确性。
- 一周后记录研究效率与遗漏，不以满意度或测试运行秒数代替实际约十分钟阅读目标。

## 每日取证口径

1. 检查开始时记录程序提交、数据目录、instance_id、五个议题ID，以及来源页逐源状态、上次成功、预算和任务缺口；检查结束时记录变化窗口、已读范围、当天纠错/判断修订和导出位置。
2. 分开写原始返回条数、唯一新增材料、重复收取和失败；缓存重新分配不等于新网络请求。延迟注明比较的是发布时间到首次发现、最近收取，还是任务排队；发布时间未知就保留未知。GKG批次时间不是发布时间。
3. 列表证据写明分页范围，不能只以第一页20条代表全部。电脑停机、睡眠、断网、未检查和无法补齐的区间都保留原状，不修改系统时间补写成功。
4. 实际检查人记录“开始查看到找到关键新增”的用时、变化ID，以及之后发现的遗漏；浏览器/API响应时间不能代替约十分钟的用户研究效率。
5. 七日结束后逐条抽查50材料、20事件/说法、10判断的ID/版本/来源/时间/关联/未知状态/复核人，并完成十条不同类型官方材料登记复核。数量不足时保留缺口。
