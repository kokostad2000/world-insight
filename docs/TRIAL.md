## 只读快照辅助工具

`scripts/capture_trial_snapshot.py`从指定研究库以 SQLite 只读事务生成一个原子发布、不可覆盖的 JSON 快照。它要求恰好五个从未标记为 fixture 的议题；`start`还要求五题 active/followed、每题有显式且已启用的免费自动来源、运行 PID 与本机健康身份一致、运行提交可解析且工作树干净，并拒绝回填超过 15 分钟的 T0。工具记录程序提交、实例、议题/来源/任务版本历史、共享配额、精确引用闭包、收取凭据、逐议题数量与状态摘要哈希，不修改研究库。

首次、每日和结束检查分别执行一次，并为每次输出选择全新的文件名：

```bash
python3 scripts/capture_trial_snapshot.py \
  "/你的真实试运行数据目录" \
  "/你的本地试运行记录/day-01-start.json" \
  --phase start --reviewer "实际检查人" \
  --expected-instance-id "启动清单中的 instance_id" \
  --trial-start-at "刚刚固定的 ISO 8601 T0（含时区）" \
  --topic-id "议题1 ID" --topic-id "议题2 ID" \
  --topic-id "议题3 ID" --topic-id "议题4 ID" \
  --topic-id "议题5 ID"
```

后续将`--phase`改为`daily`或`end`，继续传同一个`--trial-start-at`，并增加`--start-snapshot "/启动快照路径" --expected-start-sha256 "启动命令打印的哈希"`。工具会核对哈希以及同一数据目录、instance_id、五议题、检查人和 T0；`end`在真实 168 小时前直接拒绝。目标文件已存在时也直接拒绝。JSON 中的`end_sample_readiness`只判断数量，不替代逐条人工结构核验；睡眠/断网、重复与延迟解释、纠错、实际用时和遗漏仍须真实填写。任何单次快照都保持`actual_seven_day_trial_complete=false`。

工具的[隔离合成验证](evidence/trial-snapshot-tool-validation-20260921.md)只证明只读快照、拒绝覆盖和fixture阻断行为；不能复制进本表冒充真实日期记录。
