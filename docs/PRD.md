# 国际局势研究看板 PRD

版本：v1.1  
日期：2026-09-20  
状态：开发前需求方案稿  
产品名称：国际局势研究看板（暂定）

> 产品目标：帮助用户持续理解国际局势的发展，依据可追溯的证据形成、修正和复盘判断。首版使用免费数据与人工资料整理，保留付费数据和 AI 能力的扩展接口。
>
> 本文定义拟实现的产品及验收条件，不代表功能已经实现、接口已完成联调或判断准确性已得到验证。文中的性能、配额和质量目标是开发验收要求。

## 1. 需求基线与默认假设

### 1.1 已确认的用户需求

- 借鉴 World Monitor 的多源信息整合、地理关联和局势观察思路。
- 第一阶段优先使用免费数据，付费数据及后续想法保留接入能力。
- 核心用途是洞悉国际局势发展，提高对世界的判断质量。
- 系统应支持持续研究和理解变化，能够查看判断背后的证据。
- 本地一键启动、配置检查、数据持久化、备份恢复和版本更新列为首版基础交付要求。

### 1.2 本版采用的产品假设

以下假设用于使需求可执行，尚未作为用户明确确认的偏好：

| 项目 | 首版默认值 | 变化后的影响 |
|---|---|---|
| 使用方式 | 个人自用、私有运行、非商业研究 | 公开或商业部署需重新核对数据授权、用户权限与运营要求 |
| 主要终端 | 桌面浏览器，中文界面 | 移动端先保证阅读，完整编辑适配后续排期 |
| 研究范围 | 5—10 个重点议题，可涉及全球 | 不承诺全球事件完整覆盖 |
| 研究节奏 | 每日约 10 分钟查看变化，每周一次集中复盘 | 这是使用目标，需试用验证 |
| 外部服务预算 | 默认不开启任何收费 API 或绑卡试用 | 服务器、存储、网络和本地算力成本单独计算 |
| 内容生产 | 规则自动处理＋用户人工研究 | 没有模型密钥时，核心闭环仍能运行 |
| 本地运行封装 | 首个验收平台为 macOS；提供双击入口与等价终端命令，建议以 Compose 封装运行依赖 | macOS 与 CPU 架构在验收报告中记录；具体运行引擎在技术选型阶段确定 |
| 实现路径 | 先定义独立产品契约，技术选型阶段决定复用原项目或独立开发 | 复用 World Monitor 代码前核对许可证、依赖及维护成本；本文不默认已选择 fork |

### 1.3 与 World Monitor 的关系

保留多源信息、地理与时间背景、变化观察、来源追溯和依赖降级的设计思想。首版将研究重心放在议题与证据上，减少实时航空、完整船舶、专业证券等成本较高的内容。

本产品不是 World Monitor 官方版本。原项目的 CII 等指数有特定输入和方法，本版不直接复用名称或分值含义；关键输入缺失时，不以零填补并继续发布完整指数。[S01][S02]

## 2. 用户、问题与价值

### 2.1 核心用户

长期关注国际关系、安全、经济与产业变化的个人研究者。用户具备基本新闻阅读能力，希望降低整理资料的成本，并检验自己的解释是否站得住脚。

首版由同一个用户承担阅读、资料补充、判断审阅和来源管理。多人协作与审批流不在 P0 范围。

### 2.2 需要解决的问题

1. 资讯分散、重复、更新快，难以识别真正的新变化。
2. 事实、当事方说法、评论与模型推断经常混在一起。
3. 同一消息被大量转载，容易被误当作多方独立证实。
4. 热点缺少历史、资源、利益和约束背景，难以理解发展方向。
5. 用户的旧判断和修改原因没有记录，难以复盘误判。
6. 免费数据存在覆盖和时效差异，缺数据容易被误解为没有事件。

### 2.3 产品应帮助回答的问题

| 研究问题 | 产品输出 |
|---|---|
| 发生了什么？ | 新事件、原始材料、当事方说法及时间线 |
| 相较过去有什么变化？ | 新行动、新参与方、范围变化、政策状态变化、证据更正 |
| 各方的诉求与约束是什么？ | 公开立场、实际行动、经济与资源背景，注明分析依据 |
| 影响可能向哪里传导？ | 分段列明证据的影响路径，标注尚未验证的环节 |
| 接下来可能怎样发展？ | 少量竞争性情景及对应观察信号 |
| 什么会改变我的判断？ | 反对证据、失效条件、复查日期与判断版本记录 |

## 3. 目标、边界与成功标准

### 3.1 首版目标

- 支持用户独立完成“创建议题 → 收集资料 → 梳理事件 → 形成判断 → 跟踪变化 → 修订复盘”的完整闭环。
- 每条正式研究判断能追溯到材料或明确标注的假设；关键未知项可见。
- 用户可以快速理解“自上次阅读以来变化了什么”，而不是重读所有资料。
- 采集失败、模型缺失和未购买数据时，已有资料及人工研究能力继续可用。
- 文档列明的首次准备完成后，用户能一键启动本地看板；研究记录在重启和升级后保留，并可通过经过验证的备份恢复。

### 3.2 首版不承诺的能力

- 完整、即时的全球战况、军事部署或船舶位置。
- 自动识别国家真实意图、证明复杂因果关系或保证预测正确。
- 面向交易的实时证券行情或投资买卖建议。
- 缺乏校准依据的精确风险概率和国家综合风险排名。
- 自动抓取任意网页全文、绕过登录或付费墙、默认复制新闻图片。
- 多租户、团队权限、公开发布平台、外部邮件或即时通信推送。

### 3.3 成功标准

| 维度 | 验收或试用目标 | 测量方式 |
|---|---|---|
| 闭环可用 | 至少 5 个议题可以完整完成研究与复盘流程 | 使用验收数据执行端到端用例 |
| 可追溯性 | 所有已审阅判断保留证据引用或明确缺证据标记，以及假设和版本 | 数据约束检查＋页面抽查 |
| 状态诚实 | 关键缺口、来源失效、争议和更正在相关判断旁可见 | 故障与纠错场景验收 |
| 使用效率 | 试用用户能够在约 10 分钟内找出关注议题的关键新增变化 | 连续 7 天试用，记录完成时间与遗漏 |
| 支出控制 | 默认配置不会产生外部付费 API 请求 | 网络调用记录、适配器配置和预算测试 |
| 本地交付 | 一键启动、配置分级检查、跨版本持久化、备份恢复和失败回退均可验证 | 在实际 macOS 环境执行 AC-24 至 AC-36，保留版本与运行记录 |
| 判断质量 | 能保存可复查判断并说明修订原因 | 周复盘记录；不预设未经测试的“准确率提升”数值 |

判断准确性需要更长周期、明确结果标准和足够样本来检验。首版先建立可复盘记录；预测校准统计放入 P1，不用用户满意度替代准确性。

## 4. 核心概念与数据语义

| 对象 | 定义与必须区分的边界 |
|---|---|
| 议题 Topic | 一个可持续研究的问题，包含地区、参与方、时间范围、关键词和关注理由 |
| 来源 Source | 发布机构或数据提供者，记录获取方式、语言、覆盖、授权与运行状态 |
| 材料 Evidence | 文章、官方文件、数据记录或用户摘录；有原始链接、时间和版本 |
| 说法 Claim | 某主体对某事的具体主张；“某方宣布停火”不等于“停火已实施” |
| 事件 Event | 具有时间、地点和参与方的事件记录，可同时存在冲突说法 |
| 指标 Observation | 带数值、单位、观测期和发布期的统计数据；不与事件混存 |
| 判断 Judgment | 用户对局势的解释或预期，引用材料、假设、反证、置信理由和适用期限 |
| 情景 Scenario | 一个可能的发展路径，包含支持／反对证据、观察信号和失效条件 |
| 变化 Change | 新事实、事件更新、证据更正、判断修改或数据状态变化 |
| 复盘 Review | 对先前判断及结果的检查，保留当时信息条件和错误原因 |

“已审阅”表示用户完成审阅，不表示系统证明了客观真相。来源身份、材料类型、核实状态与分析置信度是不同字段，不合并成一个通用分数。

## 6. 信息架构与页面要求

### 6.1 首页：变化简报

目的：用户打开后能回答“哪些事情值得我今天重新看一遍”。

- 顶部提供“自上次阅读、24 小时、7 天、自定义”窗口；“自上次阅读”展示当前关注范围内尚未标记已读的变化，按发现时间排序，并显示原事件时间。固定时间窗口按发现时间筛选，事件统计另用事件时间。
- 显示关注议题卡片：研究问题、最近重要变化、当前判断、待重审标记、资料截至时间。
- 重要变化按类别展示：新事件、政策状态变化、原材料更正、判断修订、关键来源失效。
- 自动采集但尚未核查的信息有单独标识；用户可以查看，不能混成已确认事实。
- 优先级规则公开可解释：证据更正和到期复查优先，用户置顶与明确关注规则其次；新闻量不单独触发“风险升级”。
- 无新变化时显示“所选范围未发现新增记录”，同时显示来源覆盖；来源全部失败时显示“无法判断是否有新变化”。
- 用户显式点击“标记已读”，只标记当前筛选下已加载、已展示的变化 ID 与版本，时间上界为本次页面加载快照。分页未加载、过滤排除、阅读期间新到或已更新的变化保持未读；复查与核查待办不会因此完成。
- 新用户默认看近 24 小时，并为关注范围建立初始阅读基线；更早资料可从历史窗口访问，不伪造过去的阅读行为。

### 6.2 议题档案

页面顺序：研究问题与范围 → 最新变化 → 当前判断 → 事件时间线 → 证据与分歧 → 发展情景 → 影响路径 → 国家背景 → 版本记录。

- 头部说明议题地区、参与方、研究期限、关键词、排除词及覆盖缺口。
- 时间线可按事件时间／发布时间切换，筛选材料类型与核实状态。
- 地图与时间线选择联动；无法精确定位时只显示国家／区域，不伪造精确点位。
- 同一事件中相互矛盾的伤亡、责任、地点等说法并列保留。
- 用户可以将不相关资料移出议题，资料仍保留在原记录中。
- 无当前判断时显示“尚未形成判断”，提供整理依据的入口。

### 6.3 证据详情与待核查区

- 显示原文标题、链接、发布者、作者（若有）、语言、材料类型和各时间字段。
- 展示引用它的说法、事件、判断和情景，以及原始出处和转载关系。
- 显示用户摘录、备注、核查状态和变更历史；译文与原文分开展示。
- 原链接失效时保留已有合法元数据与引用，标记不可访问，不伪造可读全文。
- 支持登记来源关系、标记更正／撤回、拆分误合并、补充相反证据。

### 6.4 我的判断与复盘

- 按议题、复查日期、状态和结论变更筛选。
- 对照旧判断与新判断，查看当时引用的材料版本。
- 区分局势解释与可判定预测；预测必须有期限和结果判定条件。
- 结果可标为符合、不符合、部分符合、无法判定，并附依据和理由。
- “无法判定”不算预测失败，也不计入成功率；单独报告数量和原因。
- 用户可以导出议题或复盘包，包含引用、未知项、版本与生成时间，不导出服务密钥。

### 6.5 来源与设置

- 展示已启用、未配置、人工导入、额度受限、失败及数据陈旧的来源。
- 展示最后尝试、最后成功、源数据截至时间及下次计划检查。
- 提供刷新间隔、采集范围、免费配额和预算上限设置。
- 授权信息未知的来源默认只登记链接，不进行批量内容采集。
- 付费或绑卡试用适配器默认禁用；界面更改前能看到对应能力与费用性质。

## 7. 核心用户流程

### 7.1 新建议题

1. 用户填写研究问题、地区／参与方、时间范围与关注理由。
2. 配置关键词和排除词，选择可用来源；系统展示各来源覆盖与缺口。
3. 首次采集或手工登记材料，精确重复项归并，疑似重复项进入候选列表。
4. 用户筛选材料并创建／关联事件；来源不足时保持“待核查”。
5. 用户形成首个判断，记录证据、假设、反对材料和下次复查日期。

### 7.2 每日阅读

1. 打开首页，选择“自上次阅读”。
2. 查看重要变化与受影响判断，进入议题检查原始材料。
3. 接受、纠正或移除候选关联，补充未知项。
4. 保持或修订判断；修订时填写原因并形成新版本。
5. 标记已读，未完成的核查和复查项继续保留。

### 7.3 证据更正

1. 自动采集发现源内容变化，或用户登记更正／撤回。
2. 创建材料新版本，保存差异和发现时间；普通格式变化不自动当作事实更正。
3. 已确认的实质更正沿引用关系标记受影响内容为“待重审”。
4. 用户看到更正原因及相关判断，选择维持、修订或撤销判断。
5. 旧版本保留原样，新版本记录处理理由；不改写过去的研究记录。

自动变更检测仅覆盖已接入且允许持续获取的字段；未接全文的文章不能宣称已检测全文更正。用户可随时人工登记遗漏的更正。P0 传播范围仅包括系统内已登记的引用依赖，无法自动发现外部或未登记的引用。

P0 的自动化限定为结构化字段转换、精确去重、许可范围内的版本差异和明确规则匹配。实质更正、事件关联及冲突说法由用户确认；自由文本语义抽取不作为 P0 必需能力。

### 7.4 周复盘

检查到期判断 → 对照结果条件与证据 → 记录结果 → 分析错误来源 → 修改观察信号或资料范围 → 导出复盘。

### 7.5 首次安装与日常启动

1. 从代码仓下载项目，按 README 完成所需 Git／运行引擎等首次安装；私有仓库访问由用户已有 GitHub 登录完成，应用不收集其登录凭据。
2. 运行初始化或启动入口；缺少本地配置时依据 `.env.example` 创建，不覆盖已有配置。未填写可选数据源密钥不阻止进入核心看板。
3. 配置检查验证依赖、端口、数据目录和数据库版本；阻断项显示具体修复方式，可选项只提示对应能力不可用。
4. 启动后端、页面服务及采集调度，等待核心健康检查通过，再打开本地访问地址；第三方数据源离线不应阻止历史阅读。
5. 后续双击同一入口即可启动；服务已运行时直接打开既有实例，不重复启动采集任务。
6. 停止入口先停止新采集并安全结束写入，只关闭本项目实例，不删除数据库或处理其他程序。

### 7.6 更新与恢复

1. 更新入口展示当前程序版本、目标版本、数据库版本、变更说明和工作区状态。
2. 工作区存在未提交修改或未跟踪文件时，默认暂停原目录更新并说明原因；用户可以先处理修改，或选择独立目录安装新版本，原目录保持原样。
3. 依赖和目标版本下载准备完成后进入维护状态，暂停采集及用户写入，建立一致性备份；备份失败时终止更新。
4. 执行数据库迁移并启动目标版本，验证核心健康状态和数据完整性。全部通过后结束维护并恢复写入。
5. 切换完成前发生迁移或健康检查失败时，将程序与数据库成对恢复，显示失败步骤、恢复结果和重试方式。
6. 手动恢复先在独立临时目录验证备份，展示将替换的数据范围并保留当前恢复点，再执行用户明确选择的替换。

切换完成且已产生新写入后，回退属于单独恢复流程：先备份现状并检查兼容性与差异，不得静默覆盖新记录。没有兼容回退路径时保持维护状态并给出恢复方案，不启动旧程序读取不兼容数据库。

## 8. 分析与内容规则

### 8.1 事实、说法和判断

- 官方声明可以证明“该主体公开作出这一表述”，其内容是否落实需要进一步证据。
- 结构化字段与规则产生的事件关联先作为候选；P1 若引入语义抽取也遵循相同规则。原始结构化数据保持来源所给状态，不自动提升为独立核实。
- 判断标记为用户提出或模型建议；“用户已审阅”与“来源交叉核实”分别表达。
- 已审阅判断必须有证据引用，或明确说明它是基于何种假设的暂定判断；不能留空而显示确定结论。
- 仅基于假设的判断统一标为“假设型暂定判断／缺乏证据支持”。用户可以完成审阅，但该标记不会随审阅消失；首页与导出均保留此边界。

### 8.2 去重与独立性

- 自动精确去重依据规范 URL、源记录 ID、相同内容指纹；保留所有出现渠道。
- 标题相似、主题相同只产生候选，不自动合并不同事件。
- 保存已识别的原始出处与转引关系；共同引用一份声明的报道不能自动视为独立证实。
- 分别展示报道数、已识别来源链数及独立性未确认项数。来源链数不是“事实已证实次数”。
- 允许用户拆分错误合并；被影响的计数、事件和判断需要重新检查。

### 8.3 时间、位置与统计口径

- 区分事件时间、材料发布时间、材料更新时间、采集时间和用户发现时间。
- 事件时间允许未知，允许仅到日／月的精度；不能用采集时间补成精确发生时间。
- 所有时间存储为可明确解释的时区与精度，界面显示用户本地时区；历史日期不因转换而伪造时间精度。
- 位置必须记录精度：坐标、城市、区域、国家、未知；国家级记录不能显示为已知震中或冲突点。
- 指标保留观测期、发布期、单位、频率和修订版本；年度数据不因每天重新拉取而成为实时指标。
- 历史统计覆盖期不足时显示不足。P0 可以展示原始计数变化，不做缺少基线的“异常倍数”或风险解释。

### 8.4 分歧与来源偏差

- 相互冲突的数值和责任归属并列展示，禁止无依据取平均或合并成单一事实。
- 记录材料原始语言、发布机构和可识别的转引关系；不同语言不自动意味着独立来源。
- 来源地域／语言覆盖可查看，用于发现盲区，不将来源国籍直接当作真伪判断。
- 对同一判断保留支持与反对证据，按可追溯性和材料质量评估，不强制不同立场权重相等。

### 8.5 情景与置信度

- 用户可维护 2—3 个竞争性情景；没有足够材料时允许不建立情景，显示研究缺口。
- 每个已审阅情景包含适用期限、假设、支持材料、反对材料、观察信号和失效条件。
- 未找到反证时填写“尚未找到”及检索说明，不要求编造反方材料。
- P0 使用低／中／高分析置信度及文字理由，由用户确认；不自动将其映射为事件发生概率。
- 置信理由说明证据质量、独立性、争议和关键假设；不以链接数量直接计分。
- 情景变化不自动产生外部行动建议或替用户做决策。

### 8.6 影响路径

每个路径由若干相邻节点和关系组成，例如“航道受限 → 运输时间变化 → 某类供应承压”。每段关系分别标注：已观察到的关联、有证据支持的分析假设、待验证；相关并不自动构成因果。

P0 使用结构化列表编辑与阅读，无需复杂关系图编辑器。不同环节可引用不同时间和地区的数据，不得省略口径差异。

### 8.7 AI 扩展边界

- P0 模型功能关闭，采集、筛选、人工判断、模板简报和复盘不依赖模型。
- P1 模型用于摘要、翻译、候选关联和分析草稿，输出需要指向实际提供的材料 ID。
- 不存在的引用、无材料支持的数字不得进入正式简报；AI 草稿中无依据内容必须标为待核查。
- 来源内容按不可信数据处理，不得让其中的指令改变系统权限、调用任意工具或泄露密钥。
- 用户判断不得由 AI 静默覆盖。启用云模型前配置材料可发送范围、预算、日志和提供者。
- 数据源对 AI 使用有额外限制时，禁止进入默认 AI 输入集合；例如 FRED 需单独核对当前条款。[S14]

### 10.3 API 领域边界

| 路径组 | 用途 |
|---|---|
| `/api/dashboard` | 首页变化聚合、覆盖状态、阅读窗口 |
| `/api/topics` | 议题管理、资料关联、关注与归档 |
| `/api/evidence`、`/api/claims` | 材料版本、说法、出处关系和核查 |
| `/api/events`、`/api/metrics` | 标准化事件、指标和地图筛选 |
| `/api/judgments`、`/api/scenarios`、`/api/impact-paths`、`/api/reviews` | 人工研究、版本、情景、影响路径、复盘 |
| `/api/changes`、`/api/notifications` | 新增／更正／待重审变化与站内提醒 |
| `/api/sources` | 来源可用性、数据年龄、配额、授权范围与能力 |
| `/api/briefs` | P0 模板简报；P1 可增加带引用的模型草稿 |
| `/api/tracks` | 预留船舶／航空数据；P0 明确返回未配置 |
| `/api/exports` | 议题、判断与复盘包导出 |

- 查询接口使用领域对象，前端不绑定供应商原始格式。
- 正常空结果返回空列表及 `empty_reason=no_matches`；未配置或不可用返回明确状态，不能伪装为空结果。
- 可用缓存发生过期时返回原记录与 `data_status=stale`、数据截至时间及上游状态；无缓存且请求失败返回可解释错误。
- 记录新鲜度与来源运行状态独立表达：年度数据仍可能是最新已发布版本，采集刚成功也可能只得到旧数据。
- 聚合接口另返回 `coverage_status=complete/partial/unavailable/not_configured` 与逐源状态。`complete` 仅指当前查询所配置来源的检查完成，不表示世界信息完整；一源成功无结果、另一源失败时必须为 `partial`，不能只返回 `no_matches`。
- 已读更新提交实际已展示的变化 ID、版本和页面快照上界；服务端不得将该上界之前所有记录整体设为已读。
- 编辑判断带 `expected_version`；版本冲突返回冲突信息，不静默覆盖。
- 列表支持分页、议题／时间过滤；导出内容按授权范围过滤。

### 10.4 提供者扩展契约

每个适配器声明：领域能力、覆盖地区、历史深度、数据频率、认证方式、授权范围、计费单位、预算、获取／标准化逻辑和健康状态。

接入付费服务时复用领域契约；新增字段不覆盖旧数据的来源与版本。供应商互相替代前应核对覆盖、时效、字段含义和展示权限，不能仅凭接口形状相同就认为等价。

## 11. 非功能需求

### 11.1 性能与可靠性

- 初始容量基准：10 个议题、20,000 条材料、5,000 条事件／说法记录、5 个并发阅读会话；不含大型全文语料。
- 在记录了硬件、网络和缓存条件的验收环境中，首页首个可用内容 P95 不超过 3 秒，常用筛选 API P95 不超过 1 秒；测试报告必须保留环境与结果。
- 上游采集不阻塞页面读取。默认展示最近成功数据及其年龄。
- 每源独立重试和退避，避免一个故障源阻塞其他议题。
- 同一抓取批次可幂等重跑；分页中断可恢复，避免重复插入与重复提醒。

### 11.2 安全与内容边界

- 本地默认仅监听本机。若部署到远程主机，访问认证必须在暴露服务前配置；公网匿名访问不属于本版默认模式。
- 密钥仅服务端保存，日志、导出和浏览器响应不包含密钥或完整认证头。
- 获取远程资料仅通过已登记的域名与适配器；任意链接登记不意味着自动抓取，阻止访问内网地址及危险重定向。
- 外部标题、摘录和模型输出按不可信内容转义，限制渲染能力。
- 用户研究记录默认不发送给第三方模型；外发能力由独立配置控制。

### 11.3 存储与恢复

- 议题、人工注释、判断、引用版本和复盘保留至用户主动删除；删除操作提供影响预览和备份导出。
- 未引用的候选资料默认保留 90 天，可配置；第三方内容保留上限按来源授权执行，较短期限优先。
- 原文变更时保留允许存储的元数据、摘录与摘要差异，不默认建立全文镜像。
- 提供本地备份和恢复；验收需要在空实例恢复一个完整议题及其引用关系。
- 删除或撤回内容不静默消除依赖记录；必要时保留不包含受限正文的失效占位及处理原因。

### 11.4 可用性

- 状态同时使用文字和视觉标记，不能只靠红绿颜色。
- 长标题、中文与英文混排、未知时间、超长来源名都有可读布局。
- 搜索和筛选支持键盘操作；地图信息提供可替代的列表入口。
- 页面区分首次空态、未配置、无匹配结果、来源失败、额度暂停、数据陈旧、证据争议和无权展示。

### 11.5 本地运行基础交付要求

本节定义 FR-11 至 FR-15 的交付契约。以下脚本入口是待开发产物，不代表当前已有可运行应用。

#### 11.5.1 一键启动与停止

- macOS 提供 `start.command` 双击入口，并调用统一的 `scripts/start.sh`；路径中包含空格或中文时仍可正确启动。
- README 区分首次安装和日常运行：首次需要安装的依赖及版本范围明确列出，不将“一键启动”解释为无运行环境也能运行。
- 服务启动、健康检查、浏览器打开按顺序执行；核心服务未就绪时不显示启动成功。超时后说明失败步骤和脱敏日志位置。
- 核心健康状态只检查本地应用及数据存储；第三方源不可达作为降级状态，不能让历史数据页面无限等待。
- 重复启动复用现有实例；实例身份、端口与数据目录可核查，不重复创建调度器。其他应用占用端口时给出修改端口的方式，不自动结束该应用。
- 提供 `scripts/stop.sh`，以正常停止方式结束本项目服务；容器停止、重建和一般清理流程均不删除数据卷或外部数据目录。
- 电脑睡眠或关机时采集暂停。恢复运行后使用已保存检查点，在免费预算与上游支持的历史窗口内补采；无法补齐的区间保留缺口，不伪装为连续监测。

#### 11.5.2 配置检查

- 提供 `scripts/check-config.sh`，启动前自动执行本地检查，也可单独运行。输出“通过／警告／阻断”及明确修复步骤，阻断时返回非零退出码。
- 必需检查：运行依赖及引擎状态、配置格式、端口、数据／备份目录权限、可用磁盘空间、数据库版本兼容性。
- 可选检查：免费源凭据、模型和预留能力。缺失可选密钥时显示未配置，不阻止核心应用运行；格式错误仅阻断或停用受影响的来源。
- `.env.example` 只包含字段、空值或非敏感示例。创建配置时不覆盖用户已有 `.env`；配置变更不自动扩大监听范围或启用收费适配器。
- 默认检查不调用外部模型或数据 API；可选择单独的免费源连通性探测，本地检查结果与网络结果分别报告。
- 所有检查、错误和日志均脱敏；不得输出密钥原值、认证头或携带凭据的完整 URL。

#### 11.5.3 数据持久化

- 程序目录、研究数据目录、缓存、日志和备份有独立位置。数据目录路径通过本地配置指定，默认位于程序版本目录之外，并可在设置页查看。
- 数据库及必要附件必须持久化；若使用容器，存放在明确的持久卷或外部挂载目录中，不能依赖容器可写层。
- 议题、材料版本、判断、复盘、阅读进度、关注与非敏感来源配置跨正常停止、异常退出、重启和代码更新保留。
- 临时缓存允许重建；清缓存不能影响人工研究记录及其引用版本。
- 换用程序目录时必须重新确认现有数据目录；找不到既有数据时提示选择或显式创建，不静默初始化空库造成数据丢失的错觉。
- GitHub 管理代码和非敏感配置模板；`.env`、数据库、附件、缓存、日志和备份排除在 Git 追踪之外。仓库同步不能替代研究数据备份。

#### 11.5.4 备份与恢复

- 提供 `scripts/backup.sh` 与 `scripts/restore.sh`。P0 支持手动备份和每次升级前自动备份；其他定时备份为可选配置。
- 使用数据库支持的一致性快照或受控停止写入的方式备份。若采用 SQLite，不得只复制仍在写入的主数据库文件而忽略日志及一致性问题。
- 备份包包含数据库、恢复所需且允许保存的附件、非敏感配置、创建时间、程序版本／提交、数据库版本、文件清单及校验值。
- 默认不包含密钥、认证凭据或完整 `.env`；恢复到新机器后重新填写可选凭据，原有密钥配置不得被空模板覆盖。该排除项在备份完成提示和 README 中写明。
- 只有全部文件写入且校验完成后才标记成功；中断、磁盘不足或校验失败的包标为不完整，不能替代上一个有效备份。
- 恢复先核验清单、校验值、格式和数据库兼容性，并在独立临时目录检查记录数量及引用完整性；校验失败不触碰现有数据。
- 替换现有数据前展示目标目录、版本与受影响范围，建立当前状态恢复点，用户明确选择替换后再切换；不把恢复实现为不提示的覆盖复制。
- 升级与恢复点不得被自动轮转删除至无法回到最近一次成功状态。手工导出的备份不随代码清理或自动轮转删除。
- 验收必须完成实际的“备份 → 空实例恢复 → 页面读取和继续编辑”，仅能生成压缩包不算完成恢复能力。

#### 11.5.5 版本更新与迁移

- 提供 `scripts/update.sh`，使用明确可追溯的目标版本或提交；显示当前版本、目标版本、兼容条件和更新说明。不得在后台自动切换运行版本。
- Git 工作区含未提交修改或未跟踪文件时暂停原目录更新；不得执行强制重置、清理或自动丢弃。独立目录安装须保留原工作区和明确的数据目录引用。
- 目标版本获取／依赖准备失败时，不修改数据库或破坏现有可用版本。默认不要求应用运行过程中持续连接 GitHub。
- 暂停写入后执行升级前备份，记录旧程序与数据库版本；备份失败或可用空间不足时不开始迁移。
- 迁移需要有版本记录、可恢复检查点和防重复机制；中途退出后可以安全重试或恢复，不能重复应用已完成的数据变换。
- 切换前验证目标版本的本地健康状态、关键表及引用、已有议题可读性。成功后才恢复采集与用户写入。
- 迁移或切换前健康检查失败时，恢复旧程序及与之兼容的数据库和必要附件快照；不得只退代码并让其读取不兼容数据库。
- 更新成功后已产生新写入时，不自动还原旧快照；按第 7.6 节另行处理，保留现状与差异，避免丢失新研究记录。

| AC-26 | 中文／空格路径内启动，再次启动及正常停止 | 双击与终端均可运行，重复启动复用同一实例，不产生重复采集器；停止不删除数据 |
| AC-27 | 可选密钥缺失、一个来源配置错误或联网探测失败 | 核心功能可用；问题来源明确停用／降级；本地检查和网络结果分别显示，默认不调用收费接口 |
| AC-28 | 正常退出、异常终止、容器重建，以及换用程序目录后打开原数据 | 人工记录、证据版本、关联、阅读进度和设置保留；缓存可重建；不会静默建空库冒充原数据 |
| AC-29 | 运行中备份，以及备份途中磁盘不足／中断 | 有效备份一致且清单校验通过；失败包不标成功，不覆盖上一个有效包；升级前备份失败即停止升级 |
| AC-30 | 备份恢复到空实例，再打开页面继续编辑 | 数据、合法附件、版本、阅读状态和引用关系可用；密钥不在默认备份中，重新填写后对应来源恢复 |
| AC-31 | 损坏／不兼容备份，或向已有数据目录恢复 | 损坏与不兼容包被拒绝且原数据不变；有效替换先预览并保留当前恢复点，需用户明确选择替换 |
| AC-32 | 工作区同时存在修改文件和未跟踪文件时更新 | 原目录更新暂停或使用明确选择的独立目录；两类修改均保留，不执行强制重置或清理 |
| AC-33 | 迁移中断，以及迁移后切换前健康检查失败 | 恢复兼容的旧程序与数据库／必要附件；旧议题可读，错误可见，重试不重复迁移 |
| AC-34 | 升级成功并产生新记录后请求回退 | 不自动用旧快照覆盖；先保留当前状态并核对兼容性，无法安全回退时明确停止，新增记录仍可找回 |
| AC-35 | 已完成依赖下载后断开 GitHub，或更新下载失败；检查正常 Git 提交范围 | 本地历史阅读仍可用，更新失败不破坏旧版本；密钥、数据库、附件和备份未被纳入追踪 |
| AC-36 | 本机睡眠后恢复，存在采集中断区间 | 调度器只恢复一份，有限预算内补采；超出上游历史支持的区间标为缺口，旧事件不会伪装成当前发生 |

### 12.1 真实数据验证门槛

- 至少跑通 GDELT、一个许可明确的 RSS 和 World Bank 白名单指标；若某源在部署网络不可用，记录原因并以同类免费源完成等效验证，更新接入登记。

- 抽查不少于 50 条材料、20 个事件／说法和 10 条判断的来源、时间与关联；这是结构质量验收，不等于对国际局势预测准确性的验证。
- 未完成上述项目时标记“尚未完成真实数据验收”，不以单元测试通过替代。

### 12.2 本地运行验收门槛
