## 正式浏览器容量补验

同一本机另建独立容量库，端口8892、关闭采集调度。Codex内置浏览器5个真实标签页同时完整reload；先1轮预热，随后8轮共40样本。页面成功装入全部首页内容后两次requestAnimationFrame记录从navigation timeOrigin起的耗时；loading/error不会记为成功。DOM核对首页标题、10议题卡、当前判断和筛选控件确已呈现。五个导航每轮启动相差最多44.1毫秒，证明确有重叠会话。

当时实测P95 **818.1毫秒**，最大855.3毫秒；低于PRD3秒目标。原始40条浏览器读回样本、导航时间、预热值、前端SHA256、环境及边界见`browser-performance-capacity.json`。该批位于最终收取凭据和恢复净化接线之前，因此只保留为中间证据。

## 最终整合复测

最终代码在相同容量、并发与计时方法下重新运行 API 和浏览器两组测试。API 最终原始报告为 `policy-performance-final-integrated.json`：常用材料筛选 P95 **0.360秒**、关键词搜索 P95 **0.489秒**、完整议题 bundle P95 **1.629秒**；PRD 对常用筛选 API 的 1 秒门槛通过，bundle 没有冒充筛选门槛。`policy-performance-final.json`保留此前收取投影边界修复前的中间结果，不用于最终结论。

浏览器最终批次仍为5个真实标签页、8轮共40样本，每个样本逐一核对首页标题、10个议题卡和10个当前判断。一次预跑发现旧容量库的局部来源记录缺少 `budget_daily`，导致来源列表500；修复并加入回归后先确认来源接口200，再重新开始正式计时，预跑数据全部排除。最终 P95 **703.5毫秒**，最大 **723.8毫秒**，每轮五次导航起点最大相差 **16.10毫秒**，40/40 DOM有效，浏览器控制台0错误，低于3秒门槛。原始样本、代码SHA256、环境和限制见 `browser-performance-final.json`。

最终结论仅覆盖暖本机、空正文合成容量、读取并发。它不证明冷启动、大型全文、采集写入竞争、其他硬件或七天运行表现。
